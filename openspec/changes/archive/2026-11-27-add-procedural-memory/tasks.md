# TDD 实施清单

每项行为先写失败测试，提交最小实现后复跑；完成条件见 R1–R7。

## 1. Phase 0 基线

- [x] 1.1 固化普通问答、论文证据和 V2 写入回归样例，准备带反馈与后续新问题的分时段数据集（R6、R7）。
- [x] 1.2 固化四种配置、相关性阈值和上下文预算，记录模型、种子与评分规则（R4、R7）。

## 2. Phase 1 写入

- [x] 2.1 实现新增表迁移、旧库升级验证、Skill 校验与来源追踪（R1、R2、R7）。
- [x] 2.2 接入触发器、反思、判断和事务；覆盖一次性指令、重复反馈、并发修订及恢复（R1–R3）。

## 3. Phase 2 检索

- [x] 3.1 实现本地平面检索基线、在线归簇、两阶段排序，验证空库、弱匹配与跨会话召回（R4）。
- [x] 3.2 实现待同步重试、旧版过滤、撤销、中心修正和重建，注入故障验证恢复（R3、R5）。

## 4. Phase 3 Generator

- [x] 4.1 通过普通问答入口接入预算受限的策略区和注入追踪，验证冲突优先级及空上下文兼容（R6）。
- [x] 4.2 运行反馈 → 新会话 → 召回 → 回答的端到端样例，检查禁用、撤销及论文证据回归（R5–R7）。

## 5. Phase 4 评测验收

- [x] 5.1 执行四组实验，保存配置、逐例输出、命中、任务达成和开销，报告差异（R7）。
- [x] 5.2 运行迁移、单元、集成及原有测试，记录启停、重试和重建步骤；逐项核验 R1–R7 后归档。
